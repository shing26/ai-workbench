# AI 工作台设计方案

基于个人用户档案（`user-profile.md`）与 `/grilling` 访谈结论整理。

---

## 1. 产品定位

本地桌面形态的个人 AI 工作台，定位为"编排为主、自带兜底"：

- 不重复造引擎，统一收纳 Codex CLI、各家模型 API 等现有能力。
- 一个入口完成对话、写码、学习、自动化、创收与连接。
- 数据默认不出这台机器，用户拥有完全掌控权。

核心哲学：**显式主档案定规则，项目记忆管边界，行为记忆做积累，分级授权守底线。**

---

## 2. 六大模块

| 模块 | 职责 |
| --- | --- |
| 对话中枢 | 统一接入多模型/多服务，按任务路由，一个入口切换 |
| Vibe coding 工场 | 模糊想法到可运行代码的完整循环 |
| 知识中枢 | 双向闭环：沉淀学习内容，产出可教他人的文档 |
| 自动化执行台 | 定时任务、监控、抓取、批量处理 |
| 创收工作台 | 变现模板库 + 想法到产品发射台 + 收入仪表盘 |
| 连接组织层 | 分级推送、冷落项目召回、跨时刻接住想法 |

---

## 3. 核心工作流：Vibe coding 工场

1. **想法捕获**：用户一句话丢进想法。
2. **歧义澄清**：AI 问 1-3 个最关键的问题确认边界（用户明确偏好被问，而非猜测）。
3. **方案与实现**：调 Codex CLI / API 开始实现，边写边展示中间产物。
4. **运行与反馈**：自动执行、读取报错、修复、循环到可运行。
5. **用户验收**：结果摆到面前，上手体验，提修改意见继续迭代。

---

## 4. 记忆架构

三层结构，优先级从高到低：

1. **显式主档案**：`user-profile.md` 为最高优先级规则，稳定不自动改写。
2. **项目级记忆**：默认边界，每个项目独立上下文，互不污染。
3. **行为记忆**：持续自动积累，可审计、可修剪、不提供一键全清。

审计界面为组合式：

- 透明时间线：每条记录可追溯来源，可单独删除。
- 分类抽屉：按偏好/习惯/项目状态/技术栈等分类浏览与批量修剪。
- 定期快照：AI 定期输出"当前对你的理解"摘要，供确认与修改。

---

## 5. 安全与授权

分级授权模型：

| 动作等级 | 策略 |
| --- | --- |
| 读（查资料/读文件/检索） | 自动执行 |
| 写/跑（写代码/运行脚本/创建文件） | 一次确认 |
| 删/发/花（删除、发消息、付费、扣额度） | 明确批准 |

敏感信息（钱包助记词、API 密钥）存入 **Windows 凭据管理器**，工作台按需取用，不落明文文件。

---

## 6. 模型路由策略

硬件约束：3050 Ti 笔记本（约 4GB 显存），本地模型现实上限为 3-4B 流畅、7B 量化勉强。

混合路由：

- **本地模型**（Ollama + 3-4B 档）：隐私敏感任务、轻量后台、低延迟小请求。
- **云 API**：复杂推理、深度分析、高质量代码生成、长文档任务。
- **成本控制**：每月预算上限；超预算时自动降级到本地模型，或提示用户确认后继续。
- **按项目/模块统计花费**，高成本操作先报预算再执行。

---

## 7. 连接组织层

- **推送过滤**：低优先级日志静默进时间线，高优先级结果才推送通知。
- **冷落召回**：进行中项目三天未动，主动推送 + 汇总，把用户拉回。
- **想法捕获**：不强推手机端快速记录；用户习惯"回头想"，工作台负责在用户回来时帮助重建上下文、顺着半截线索找回想法。

---

## 8. 交互与视觉

- **混合式入口**：命令面板（召唤）+ 仪表盘（总览）+ 对话窗口（深协作）。
- **仪表盘密度**：进行中项目、自动化状态、收入、待办一眼全见。
- **强交互反馈**：流畅拖拽与转场、点击即时响应、快捷键全覆盖、界面元素实时联动（任务运行时进度可见）。
- **视觉基调**：默认深色主题，精致丰富 + 机能实用，拒绝纯装饰性设计。

---

## 9. 技术栈推荐

### 推荐组合

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 桌面壳 | Tauri 2（Rust） | 内存占用远低于 Electron，适合常驻后台；启动快，符合"随时召唤"体验 |
| 前端 | React + TypeScript + Vite + Tailwind | 生态成熟，适合高密度仪表盘与组件化交互；TS 与后端同语言降低切换成本 |
| 交互 | dnd-kit（拖拽） + Framer Motion（转场） | 直接满足"拖拽流畅、转场顺滑"的交互需求 |
| 编排后端 | Node.js/TypeScript 进程 | 与前端同语言；原生支持调用 Codex CLI 子进程与各家 AI SDK |
| 本地模型 | Ollama（3-4B 档） | 一键管理本地模型，HTTP API 易于接入路由层 |
| 敏感信息 | Rust `keyring` 对接 Windows 凭据管理器 | 通过 Tauri command 安全取用，不明文落盘 |
| 持久化 | SQLite（项目/行为记忆）+ 文件系统（文档资产） | 零运维、本地优先、可审计导出 |
| 知识检索 | sqlite-vec 或本地向量索引 | 轻量，满足文档级 RAG，不上云 |

### 推荐理由（对齐个人档案）

- **少切换、少障碍**：前后端统一 TypeScript，避免"边做边学"时在多语言间来回横跳。
- **低资源常驻**：夜猫子作息下工作台长时间开着，Tauri 的低内存占用避免拖累笔记本。
- **可快速迭代**：Vite HMR + 薄 Rust 层，想法改动即时可见，契合"状态驱动、快速验证"。
- **掌控优先**：数据、密钥、模型全部本地可控，符合"万物为我所用"与不依赖云端的长期愿景。
- **能力不重复**：编排层优先调 Codex CLI / API，内置兜底只处理小任务，MVP 成本可控。

---

## 10. MVP 范围（第 1-2 周）

只做两块核心：

1. **对话中心**
   - 多模型接入（云 API + Ollama 本地模型），手动/自动路由。
   - 对话历史落 SQLite，项目级上下文隔离。
   - 每月预算记录与超预算降级提示。
2. **Vibe coding 工场**
   - 想法捕获 → 1-3 个澄清问题 → 调 Codex CLI 实现 → 运行/报错/修复循环 → 用户验收。
   - 写/跑动作走"一次确认"，删/发/花走"明确批准"。
   - Windows 凭据管理器存取 API 密钥。

配套骨架：深色高密度仪表盘、命令面板（Ctrl+K）、核心快捷键、任务进度实时联动。

后置模块：知识中枢、自动化执行台、创收工作台、连接组织层，按 MVP 验证后的实际需求逐个生长。

---

## 11. 关键设计原则

- 显式档案优先，AI 不擅自改写用户设定。
- 可审计、可修剪，但保留主档案稳定性。
- 被问可以，但只问关键问题，不问"稍微想想就能自己回答"的小事。
- 日常不打断，关键结果必达，冷落项目主动召回。
- 所有自动化越界动作过用户的手，理由充分、流程透明。
